# Промт: LLM-шлюз (транспортный слой, без астрологии)

Ты работаешь над проектом exact-orb. Детерминированный слой (натальная
карта, аспекты, конфигурации, сила планет) уже есть и логирование к нему
уже спроектировано отдельным промтом (`prompts/2026-08-17/01-logging.md`).
Сейчас нужен только транспортный слой для обращения к LLM — шлюз,
который позволяет подключать разные провайдеры (сейчас DeepSeek, позже
возможно Claude/Gemini/локальная модель через Ollama), не переписывая
остальной код при смене модели.

ВАЖНО — ГРАНИЦА ОТВЕТСТВЕННОСТИ
Этот модуль НЕ занимается астрологической интерпретацией: он не содержит
знаний про аспекты, дома, конфигурации и не решает, что и как объяснять
пользователю. Его единственная задача — принять готовый промпт (текст),
отправить его в выбранную модель, вернуть текст ответа, залогировать
запрос/ответ/стоимость/ошибки и корректно обработать сбои. Слой с
промпт-шаблонами и базой трактовок — предмет отдельного промта, не трогай
его здесь.

ЗАДАЧА
Исследуй библиотеку `litellm` (unified API к 100+ провайдерам, включая
`deepseek/*` и `ollama/*`) так же, как раньше исследовал `pysweph`: не
полагайся на память о её API, проверь фактические сигнатуры и поведение
через `inspect.getdoc`, чтение исходников пакета и пробные запуски, а не
предположения. В частности проверь актуальный формат `usage` в объекте
ответа и то, как `litellm.completion_cost(response)` считает стоимость —
это может отличаться от того, что написано в старой документации в
интернете.

ОСОБОЕ ВНИМАНИЕ
1. Не хардкодь конкретный id модели DeepSeek в коде как единственный
   вариант — DeepSeek уже сменил поколение (V3 → V4), актуальный id
   модели может снова измениться. Модель должна быть параметром
   конфигурации, а не константой в коде.
2. API-ключ (`DEEPSEEK_API_KEY` и любые другие ключи провайдеров) — только
   из переменных окружения. Никогда не читай ключ из `pyproject.toml` и не
   логируй его значение ни при каких обстоятельствах, даже на DEBUG.
3. Тесты не должны обращаться к реальному API (это платно и нестабильно
   в CI) — замокай `litellm.completion` там, где тестируется логирование,
   ретраи и обработка ошибок.

ЧТО ВЕРНУТЬ

Модуль `src/exact_orb/llm/gateway.py`:

- Pydantic-модель `LLMResponse`: `text`, `model`, `provider`, `tokens_in`,
  `tokens_out`, `cost_usd | None` (если `litellm.completion_cost` не смог
  посчитать для провайдера — не падай, оставь `None`), `latency_ms`.
- Функция `complete(prompt: str, *, system: str | None = None, model:
  str | None = None, **kwargs) -> LLMResponse` — тонкая обёртка над
  `litellm.completion`. `model` резолвится по той же цепочке приоритета,
  что путь эфемерид в `config.py`: аргумент функции > переменная
  окружения `EXACT_ORB_LLM_MODEL` > `[tool.exact_orb].llm_model` в
  `pyproject.toml` > встроенный дефолт `deepseek/<актуальный id модели>`
  (какой именно — уточни в документации DeepSeek на момент реализации,
  не бери из памяти).
- Ретраи: используй встроенный механизм `litellm` (`num_retries` /
  аналог в текущей версии) для транзиентных ошибок (rate limit, timeout,
  5xx). После исчерпания попыток — лог ERROR с `exc_info=True` и
  собственное исключение `LLMGatewayError` (с исходным текстом ошибки
  провайдера), которое вызывающий код может поймать, не завися от
  внутренних классов исключений `litellm`.
- Логирование через `logging_setup` из промта про логи:
  - на INFO/general — одна компактная строка: провайдер, модель, длина
    промпта в символах, `tokens_in/out`, `cost_usd`, `latency_ms`, статус
    ok/error;
  - на DEBUG — полный текст промпта (system + user) и полный текст
    ответа;
  - при ошибке — ERROR с traceback, без утечки ключа в сообщении.
- Настройки таймаута запроса и лимита ретраев — тоже через
  конфигурацию (env var / pyproject), не константы в коде.

ЧТО ВЕРНУТЬ (интеграция с проектом)

- Добавь `litellm` в зависимости `pyproject.toml`.
- Добавь `llm_model` (опционально) в `[tool.exact_orb]` как пример —
  не обязательно ставить туда реальный дефолт, если он должен жить в
  коде.
- Ничего не меняй в `cli.py` — интеграция шлюза с CLI/будущим агентом
  выходит за рамки этого промта.

ПРОВЕРКА

1. Замокай `litellm.completion`, верни фиктивный `ModelResponse` с
   заданным `usage` — проверь, что `complete()` возвращает корректно
   заполненный `LLMResponse` и что в лог (general и debug) попали
   правильные строки без утечки ключа.
2. Смоделируй ошибку (мок кидает исключение или возвращает 429/5xx) —
   проверь, что после исчерпания ретраев поднимается `LLMGatewayError`,
   а в логе есть ERROR с traceback.
3. Разово (не в автотестах, руками) прогони `complete()` с реальным
   `DEEPSEEK_API_KEY` на коротком промпте — сверь, что `cost_usd` и
   `tokens_in/out` выглядят правдоподобно относительно официального
   прайса DeepSeek на момент проверки.

ОГРАНИЧЕНИЯ
Не добавляй сюда ничего про трактовку карт, промпт-шаблоны для
интерпретации или базу знаний по астрологии — это отдельная задача. Не
изобретай параметры `litellm`, которых нет в установленной версии —
проверь запуском кода. Не пиши в лог и не выводи в исключениях сырое
значение API-ключа.
