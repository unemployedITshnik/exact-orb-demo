# Промт: логирование текущего функционала

Ты работаешь над проектом exact-orb: инструмент астрологических расчётов
с жёстким разделением детерминированного и интерпретирующего слоёв. Сейчас
в проекте нет логирования, кроме точечных `LOGGER.info/warning` в
`config.py` (статус эфемерид). Добавь единую подсистему логирования для
всего текущего функционала: CLI (`cli.py`), парсинг ввода, конфигурацию
эфемерид, расчёт натальной карты, поиск аспектов, конфигураций (паттернов)
и силы планет. Подсистема должна быть готова к тому, что позже поверх неё
появится интерпретирующий слой (LLM-агент) — но сам агент сейчас не
реализуем, только фундамент логирования.

ТРЕБОВАНИЯ

1. Логи пишутся локально в папку `logs/` в корне проекта.
2. Имя файла — по дате и времени UTC на момент создания файла (не локальное
   время, не время запуска процесса — именно UTC).
3. Размер файла лога подбери оптимальный сам (обоснуй выбор в комментарии
   в коде); по достижении лимита текущий файл закрывается и открывается
   новый — с новым именем по актуальному UTC-времени, а не суффиксом
   `.1`, `.2` как в стандартном `RotatingFileHandler`.
4. Несколько уровней логирования: общий (general) и отладочный (debug).
5. В логах обязательно должны быть видны сообщения пользователя (ввод —
   аргументы CLI / распарсенная дата-время-место) и ответы системы
   (результат — сводка карты / факт успешного вывода).
6. Обязательно логируются ошибки и предупреждения (включая предупреждения
   Swiss Ephemeris, которые сейчас видны только в human-выводе через
   `--no-warnings`, но нигде не логируются).

7. Формат имени файла — `YYYYMMDDTHHMMSSZ.log` (например
   `20260817T113245Z.log`). Без двоеточий: проект открывается в PyCharm на
   Windows (`.idea/exact-orb.iml` в репозитории), а `:` недопустим в имени
   файла на Windows.
8. Два потока хранения вместо одного файла с двумя уровнями "внутри":
   `logs/general/` (INFO и выше, компактная запись — одна строка на вызов
   CLI: вход, статус, длительность) и `logs/debug/` (DEBUG и выше, полная
   деталь: аргументы, промежуточные расчёты, весь текст ответа). Так
   "общий" лог остаётся читаемым человеком, а "дебаг" не теряет детали.
   Ротация по размеру и правило именования одинаковы для обоих потоков.
9. Session id: короткий uuid4 (например первые 8 символов) генерируется
   один раз при старте процесса и попадает в каждую строку лога. Это
   единственный способ склеить строки одного запуска, когда файл разбит
   ротацией на части или когда в будущем в одном файле окажутся строки
   нескольких параллельных запусков агента.
10. Заголовок сессии: первая запись в каждом новом файле — версия Python,
    версия exact-orb (`importlib.metadata.version`), режим и путь
    эфемерид (`EphemerisStatus`), house system по умолчанию. Это должно
    быть достаточно для воспроизведения расчёта позже без переоткрытия
    кода.
11. Формат строки: `UTC-timestamp LEVEL session=<id> logger=<name> msg`.
    Используй `%`-форматирование логгера (`LOGGER.debug("...%s", x)`), а
    не f-строки — иначе дорогие объекты (весь `NatalChart`) сериализуются
    даже при выключенном DEBUG.
12. Консоль: пользователь CLI по-прежнему видит только текущий
    human/JSON вывод в stdout. В файлы это же плюс диагностика уходит
    отдельно; в stderr дублируются только WARNING и выше, компактно,
    без session id — не мешать текущему UX.
13. Ретеншен: ограничь суммарный объём `logs/` (например 200 МБ на каждый
    из `general/` и `debug/`) или число файлов — при превышении удаляй
    самые старые. Без этого при частом использовании папка растёт
    неограниченно.
14. Настройки уровня/пути/размера — по той же цепочке приоритета, что уже
    используется в `config.py` для эфемерид: явный аргумент функции >
    переменная окружения (`EXACT_ORB_LOG_LEVEL`, `EXACT_ORB_LOG_DIR`,
    `EXACT_ORB_LOG_MAX_BYTES`) > `[tool.exact_orb]` в `pyproject.toml` >
    встроенное значение по умолчанию.
15. Расширь существующий паттерн `LOGGER = logging.getLogger(__name__)`
    (уже в `config.py`) на `cli.py`, `ephemeris/natal.py`,
    `aspects/finder.py`, `configurations/finder.py`, `strength/*`: сейчас
    предупреждения Swiss Ephemeris и ошибки парсинга видны только в выводе
    для пользователя, в лог не попадают.
16. Если `logs/` не создаётся или недоступна для записи (нет прав,
    read-only FS) — CLI не должен падать. Логирование должно деградировать
    до вывода в stderr с одним WARNING о недоступности файлового лога, а
    расчёт и человекочитаемый вывод — работать как обычно.
17. Замеряй длительность расчёта (парсинг → `get_natal` → аспекты →
    конфигурации → сила планет → рендер) и пиши в общий лог одной строкой:
    вход, длительность, статус (ok/error). Полезно уже сейчас — `strength`
    и `configurations` считают заметно дольше остальных модулей.
18. Ошибки логируй с полным traceback (`LOGGER.error(..., exc_info=True)`)
    на уровне ERROR до того, как CLI покажет пользователю короткое
    сообщение через `parser.exit(2, ...)` — сейчас traceback нигде не
    сохраняется, повторить баг post-hoc нечем.
19. Добавь `logs/` в `.gitignore` (сейчас там нет такой записи, хотя есть
    `data/ephe/`, `.pytest_cache/` и т.д. по тому же принципу — не
    коммитить рантайм-артефакты).

ЧТО ВЕРНУТЬ

- Новый модуль, например `src/exact_orb/logging_setup.py`:
  - `init_logging(...)` — идемпотентная настройка хендлеров (general +
    debug), вызывается один раз в `cli.py:main()` до первого лога.
  - Кастомный rotating handler (наследник `BaseRotatingHandler` или
    обёртка над `RotatingFileHandler`), который при роллове переименовывает
    новый файл по текущему UTC-времени, а не числовым суффиксом.
  - Функция получения session id и вставки его в каждую запись (например
    через `logging.LoggerAdapter` или `Filter`, добавляющий `record.session`).
- Правки в `cli.py`: логирование входа ("сообщение пользователя" — сырой
  input_text и распарсенные параметры), логирование ответа (сводка вывода
  на INFO в general, полный текст на DEBUG), логирование ошибок и
  Swiss Ephemeris предупреждений.
- Расширение `config.py` или отдельного модуля настроек — резолвинг
  `EXACT_ORB_LOG_*` по той же цепочке приоритета, что уже есть для
  `EXACT_ORB_EPHE_PATH`.
- `logs/` в `.gitignore`.
- Тесты в `tests/test_logging.py`.

ПРОВЕРКА

1. Прогони CLI несколько раз подряд с искусственно маленьким лимитом
   размера (через `EXACT_ORB_LOG_MAX_BYTES` в тесте) — убедись, что при
   превышении лимита создаётся новый файл с новым UTC-именем, а не
   дозаписывается старый.
2. Проверь, что имена файлов лексикографически сортируются в
   хронологическом порядке и не содержат `:` (валидны на Windows).
3. Проверь на реальном вызове (`2.09.1985 00.45 gmt+4`), что в
   `logs/general/*.log` есть одна компактная строка с входом и статусом, а
   в `logs/debug/*.log` — тот же вход плюс сериализованный ответ.
4. Сломай ввод (`exact-orb "мусор"`) — убедись, что в лог попал ERROR с
   traceback, а пользователь в консоли по-прежнему видит короткое
   сообщение об ошибке и код возврата 2.
5. Временно сделай `logs/` недоступной для записи (или подставь
   несуществующий путь без прав) — убедись, что CLI не падает, расчёт и
   вывод отрабатывают, в stderr одно предупреждение.

ОГРАНИЧЕНИЯ

Не полагайся на память о поведении `logging.handlers.RotatingFileHandler`
при роллове — прочитай исходники стандартной библиотеки
(`inspect.getsource` / `Lib/logging/handlers.py`) и подтверди запуском
кода, как именно вызывается `doRollover` и что нужно переопределить для
кастомного имени файла. Не изобретай не существующие параметры логгера.
Не используй f-строки в вызовах `LOGGER.debug/info/warning/error` — только
ленивое `%`-форматирование.
