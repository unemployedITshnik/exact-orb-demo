# Исправить вывод категорий аспектов и конфигураций

Исправь вывод категорий аспектов и конфигураций в exact-orb.

═══════════════════════════════════════════════════════════
ПРОБЛЕМА
═══════════════════════════════════════════════════════════

Модуль aspects/categories.py вычисляет категорию каждого аспекта
(exact / working / background), но она не доходит до вывода.
В текстовом рендере помечены только тесные припиской «← тесный»,
остальные идут сплошным списком.

Следствие: слой интерпретации вынужден определять вес аспекта
самостоятельно из числа орбиса. Это работает случайно, а не по
данным, и противоречит принципу «модель не вычисляет, а читает».

Аналогично для конфигураций: max_orb выводится числом, но без
категории. Йод с max 1°41' и йод с max 6°41' — фигуры разной
силы, и это должно быть выражено меткой, а не только цифрой.

═══════════════════════════════════════════════════════════
ЧАСТЬ 1. ТЕКСТОВЫЙ РЕНДЕР
═══════════════════════════════════════════════════════════

Заменить плоский список аспектов на группировку по категориям.
Внутри группы — сортировка по возрастанию орбиса.

Целевой формат:

```text
  АСПЕКТЫ

    ТОЧНЫЕ (орбис < 1°)
      Сев. узел  ☍  Юж. узел    0°00'
      Лилит      ⚻  Фортуна     0°25'
      Луна       □  ASC         0°26'
      Солнце     □  Фортуна     0°26'
      Уран       ☍  Хирон       0°27'
      Меркурий   □  Сатурн      0°31'
      Юпитер     ⚻  ASC         0°35'
      Солнце     ⚻  Юпитер      0°39'
      Сев. узел  ☌  Лилит       0°43'
      Юж. узел   ☍  Лилит       0°43'
      Солнце     △  Лилит       0°52'

    РАБОЧИЕ (1–3°)
      Луна       ⚹  Юпитер      1°01'

    ФОНОВЫЕ (3–7°)
      Венера     ☍  Юпитер      3°05'
```

Приписку «← тесный» убрать: категория теперь выражена структурой,
дублировать её меткой не нужно.

Пустая группа не выводится вовсе, а не выводится с нулём строк.

═══════════════════════════════════════════════════════════
ЧАСТЬ 2. КАТЕГОРИИ КОНФИГУРАЦИЙ
═══════════════════════════════════════════════════════════

Добавить поле category в модель Configuration, вычисляемое
из max_orb по тем же порогам, что у аспектов:

```text
  tight       max_orb < 3°     плотная, работает отчётливо
  moderate    3–5°             умеренная
  loose       свыше 5°         рыхлая, фоновая
```

Пороги в конфиг отдельным набором configuration_categories —
они не обязаны совпадать с аспектными, потому что фигура
собирается из нескольких рёбер и терпит более широкие орбисы.

Целевой формат вывода:

```text
  КОНФИГУРАЦИИ

    ПЛОТНЫЕ (< 3°)
      Йод           max 1°41'  apex: Солнце · base: Юпитер, Луна
      Тау-квадрат   max 2°14'  apex: Юпитер · base: Лилит, Юж. узел
      Тау-квадрат   max 2°14'  apex: Юпитер · base: Сев. узел, Юж. узел

    РЫХЛЫЕ (> 5°)
      Тау-квадрат   max 5°06'  apex: Солнце · base: Хирон, Уран
      Бисекстиль    max 6°20'  center: Юпитер · wings: Луна, Уран
      Йод           max 6°41'  apex: Луна · base: Плутон, Солнце
      Бисекстиль    max 6°47'  center: Луна · wings: Хирон, Юпитер
      Трапеция      max 6°47'  opp: Хирон–Уран · base: Юпитер, Луна
```

Ожидаемое распределение для карты 1985 года: три плотных,
ни одной умеренной, пять рыхлых. Проверь фактически.

═══════════════════════════════════════════════════════════
ЧАСТЬ 3. JSON
═══════════════════════════════════════════════════════════

Поле category должно присутствовать в КАЖДОМ аспекте и КАЖДОЙ
конфигурации в JSON-выводе. Проверь, что оно доходит из модели
до сериализации.

```json
{
  "from": "mercury",
  "to": "saturn",
  "aspect": "square",
  "orb": 0.52,
  "category": "exact",
  "applying": null
}
```

applying = null для натальной карты. Это не пропуск, а корректное
значение: в снимке одного момента нет движения, сходимость
не определена. Задокументируй в docstring, чтобы поле не сочли
недоделкой.

═══════════════════════════════════════════════════════════
ЧАСТЬ 4. ОСОБЫЕ ГРАДУСЫ В ВЫВОДЕ
═══════════════════════════════════════════════════════════

Сейчас 0° кардинального помечается у Нептуна припиской в строке
планеты, но в отдельную секцию не выносится и в интерпретацию
не попадает.

Добавить блок:

```text
  ОСОБЫЕ ГРАДУСЫ
    Нептун      0°52' Козерог     0° кардинального · критический
    Юпитер      8°41' Водолей     критический (фикс. 8–9°)
    Меркурий   22°05' Лев         критический (фикс. 21–22°)
    Сатурн     22°36' Скорпион    критический (фикс. 21–22°)
    куспид 5   29°44' Дева        анаретический
    куспид 11  29°44' Рыбы        анаретический
```

Дублирование пометки в строке планеты убрать — секция полнее
и попадает в промт синтеза как отдельный блок.

═══════════════════════════════════════════════════════════
ЧАСТЬ 5. ТЕСТЫ
═══════════════════════════════════════════════════════════

- Каждый аспект эталона попал в верную группу. Проверить границы:
  Солнце △ Лилит 0.86 → exact
  Луна ⚹ Юпитер 1.02 → working (не exact)
  Венера ☍ Юпитер 3.08 → background (не working)
- Категории конфигураций: три плотных, пять рыхлых.
- JSON содержит category во всех аспектах и конфигурациях.
- applying == None для всех натальных аспектов.
- Пустая группа не рендерится.
- Golden-файл текстового вывода обновить, diff проверить глазами.

Запусти и покажи фактический вывод CLI целиком.
