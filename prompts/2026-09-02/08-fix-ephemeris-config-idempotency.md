# Исправление идемпотентности Ephemeris runtime config

Работай в ветке:

`fix/ephemeris-config-idempotency`

Не создавай коммит, не выполняй push и не включай изменения из других веток.
Сохрани пользовательские и несвязанные изменения рабочего дерева.

## Цель

Сделать конфигурацию эфемерид детерминированной и неизменяемой после startup:

1. Повторный `configure_ephemeris()` должен проверять не только путь, но и явно
   переданный `selena_method`.
2. Тесты не должны зависеть от внешнего `EXACT_ORB_SELENA_METHOD`.
3. Поиск проектного `pyproject.toml` не должен зависеть от текущего рабочего
   каталога процесса.

Не изменять математику Селены, расчёт натала, fallback эфемерид, набор
обязательных файлов или приоритет источников конфигурации.

## Перед изменениями

Изучи полностью:

- `AGENTS.md`;
- `src/exact_orb/config.py`;
- `src/exact_orb/errors.py`;
- `tests/conftest.py`;
- `tests/test_ephemeris_runtime_config.py`;
- `tests/test_selena.py`;
- связанные тесты CLI, logging и LLM, использующие общий reader
  `pyproject.toml`;
- актуальные требования эфемеридного компонента;
- README, ADR и диаграммы, описывающие startup-конфигурацию.

Исторические файлы `prompts/**` не редактируй.

Сначала зафиксируй текущие дефекты тестами и получи ожидаемый red phase.

## Требуемый контракт

Процессное состояние эфемерид представляет собой неизменяемую пару:

```text
(normalized_ephemeris_path, selena_method)
```

После первой успешной инициализации действуют правила:

| Повторный вызов | Результат |
|---|---|
| `path=None`, `selena_method=None` | вернуть замороженный статус без повторного I/O |
| Тот же явный путь, метод не передан | вернуть тот же статус |
| Путь не передан, явно передан тот же метод | вернуть тот же статус |
| Явно переданы те же путь и метод | вернуть тот же статус |
| Передан другой путь | `EphemerisPathMismatchError` |
| Передан другой валидный метод Селены | типизированная ошибка конфигурационного конфликта |
| Передан неизвестный метод | существующий `ValueError` валидации |

Изменение environment или `pyproject.toml` после startup не должно
переконфигурировать процесс и не должно считаться конфликтом, если
соответствующее значение не передано явно.

Повторная успешная конфигурация не должна:

- повторно читать `pyproject.toml`;
- повторно читать environment как источник нового состояния;
- повторно вызывать `swe.set_ephe_path`;
- повторно писать startup-status в лог;
- заменять объект `EphemerisStatus`;
- менять уже опубликованный `_EphemerisRuntimeState`.

## Ошибка конфликтующего метода

Добавь типизированную ошибку для конфликта метода Селены, например:

```python
EphemerisSelenaMethodMismatchError
```

Она должна наследоваться от `EphemerisConfigurationError`.

Сообщение должно содержать замороженный и запрошенный методы, например:

```text
selena method is already configured as 'mean_perigee', got 'true_perigee'
```

Существующий `EphemerisPathMismatchError` и его публичное поведение сохранить.

Если одновременно конфликтуют путь и метод, сохранить текущий порядок проверки:
сначала путь, затем метод. Не менять существующее поведение path mismatch.

## Исправление fast path

Текущий ранний возврат при `state is not None and path is None` нельзя сохранять
в прежнем виде: он игнорирует явно переданный `selena_method`.

Быстрый возврат допустим только тогда, когда оба параметра не заданы:

```text
path is None and selena_method is None
```

Если метод передан явно, повторный вызов должен войти в защищённую секцию,
провалидировать метод и сравнить его с замороженным состоянием.

Это правило должно работать и при конкурентном startup: если два участника
одновременно запрашивают одинаковый путь, но разные методы, один публикует
состояние, второй получает типизированный конфликт. Backend и startup-лог
выполняются только один раз.

Для concurrency-теста используй `Barrier`/`Event`, без `sleep`.

## Детерминированный `pyproject.toml`

Сейчас `_read_exact_orb_pyproject_config_with_directory()` начинает поиск от
`Path.cwd()`. Из-за этого запуск из корня репозитория и из родительской папки
даёт разные настройки.

Зафиксируй следующий контракт:

- читается проектный конфиг самого приложения exact-orb;
- его расположение определяется стабильным корнем приложения, а не текущим CWD;
- относительные `ephemeris_path` и `log_dir` по-прежнему разрешаются относительно
  каталога найденного `pyproject.toml`;
- не использовать скрытый `os.chdir()`/`monkeypatch.chdir()` в production-коде;
- не добавлять сетевые источники, новые зависимости или отдельный
  конфигурационный сервис;
- при отсутствии проектного `pyproject.toml` сохранить существующие
  environment/default fallbacks.

Не изменяй порядок источников:

```text
явный аргумент → environment → project pyproject.toml → default
```

Учти, что общий reader используется не только эфемеридами, но также logging и
LLM gateway. Проверь связанные тесты и не меняй их значения по умолчанию.

Если стабильный корень нельзя определить без изменения публичного API или
предположения о layout репозитория, остановись и явно опиши конфликт. Не
маскируй проблему дополнительным fallback на случайный CWD.

## Изоляция тестов

Autouse-фикстура в `tests/conftest.py` не должна оставлять метод Селены зависимым
от пользовательского environment.

Общие расчётные тесты должны получать детерминированный startup-конфиг. При этом
тест, проверяющий чтение проектного `selena_method`, обязан действительно
проходить через project-config source, а не получать значение из
autouse-фикстуры или явного аргумента.

Для `test_project_config_selects_true_perigee`:

- отключи автоматическую инициализацию;
- удали `EXACT_ORB_SELENA_METHOD` через
  `monkeypatch.delenv(..., raising=False)`;
- выполни конфигурацию внутри самого теста;
- проверь, что источником метода стал проектный конфиг;
- тест должен проходить независимо от внешнего environment и CWD.

Отдельным тестом сохрани и докажи приоритет environment над `pyproject.toml`.

Не меняй production-приоритет источников только ради прохождения теста.

## Обязательные regression-тесты

Добавь или уточни тесты для следующих случаев:

1. Одинаковые путь и метод — идемпотентный возврат того же
   `EphemerisStatus`.
2. `configure_ephemeris(None, selena_method=<тот же метод>)` — успешный
   идемпотентный вызов.
3. Тот же путь и другой валидный метод — типизированная mismatch-ошибка.
4. `path=None` и другой валидный метод — та же mismatch-ошибка.
5. После конфликта замороженный путь и метод не меняются.
6. После конфликта `swe.set_ephe_path` и startup-лог не повторяются.
7. Неизвестный метод после startup по-прежнему даёт `ValueError`.
8. Повторный вызов без явных параметров не читает environment или
   `pyproject.toml`.
9. Конкурентные вызовы с разными методами дают одну успешную публикацию и один
   конфликт.
10. Внешний `EXACT_ORB_SELENA_METHOD=mean_perigee` не ломает тест
    project-config.
11. Отдельный тест подтверждает, что environment действительно имеет приоритет
    над project config.
12. Запуск project-config теста из корня репозитория и из родительского каталога
    даёт одинаковый результат.
13. Относительный `ephemeris_path` разрешается относительно каталога project
    `pyproject.toml`, а не CWD.
14. Общий reader logging/LLM сохраняет прежние приоритеты и значения.

Негативные тесты дополняй позитивным контролем. Не проверяй только приватные
поля, если тот же контракт можно проверить публичными функциями; внутреннее
состояние допустимо проверять для атомарности и неизменяемости startup.

## Документация

Синхронизируй только непосредственно связанные актуальные документы.

В требованиях нужно явно зафиксировать:

- замораживаются и путь, и метод Селены;
- повторный явный конфликт любого замороженного параметра является ошибкой;
- отсутствие аргумента означает использование замороженного состояния;
- environment и project config читаются только при первой инициализации;
- project `pyproject.toml` ищется относительно стабильного корня приложения, а
  не CWD;
- относительные пути разрешаются относительно файла конфигурации.

Проверь и при необходимости обнови:

- Т-ЭФ-3;
- Т-ЭФ-4;
- Т-ЭФ-6;
- раздел конфигурации README;
- существующий ADR или диаграмму startup, если они описывают эти границы.

Не создавай новый ADR без доказанного изменения архитектурного решения. Если
это уточнение существующего решения — оформи явную ревизию действующего
документа.

## Ограничения

Не изменять:

- формулы и golden-значения Селены;
- `mean_perigee` и `true_perigee`;
- расчёт натала и транзитов;
- fallback Swiss Ephemeris;
- `EphemerisStatus` без доказанной необходимости;
- публичные значения по умолчанию;
- приоритет argument/environment/project/default;
- кэш, ChartSpec или CalculationVersion;
- logging privacy;
- любые замечания других веток.

Не добавлять зависимости, compatibility aliases или неявную переконфигурацию
процесса.
