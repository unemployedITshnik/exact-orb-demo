# Fix ChartArtifactResolver single-flight ownership and lifecycle

Исправь два связанных дефекта конкурентности и владения данными в `ChartArtifactResolver`.

Работай только в рамках calculation artifacts. Не меняй астрологический движок, правила расчёта, нормализацию ключей кэша и публичные схемы без доказанной необходимости.

## Контекст

Основной код:

- `src/exact_orb/calculation/artifacts.py`
- `src/exact_orb/calculation/types.py`
- `src/exact_orb/calculation/codec.py`
- `src/exact_orb/calculation/cache.py`

Тесты:

- `tests/test_chart_artifact_resolver.py`
- при необходимости `tests/test_chart_artifact_codec.py`

## Дефект 1: общий mutable-артефакт

При одновременном cache miss все участники single-flight ожидают одну `asyncio.Task` и получают один экземпляр `ChartArtifact`.

Сам `ChartArtifact` заморожен только на верхнем уровне. Вложенный `chart`, его словари и модели остаются изменяемыми. Один вызывающий код может изменить результат, который уже получил другой вызывающий код.

Требуемое поведение:

- каждый вызов `ensure_chart()` должен получить собственный изолированный экземпляр результата;
- результаты должны быть равны по данным, но не идентичны по объектам;
- мутация `first.chart`, вложенных словарей или `BodyPosition` не должна изменять `second`;
- внутренний экземпляр, который кодируется и сохраняется в кэш, не должен передаваться вызывающему коду по общей mutable-ссылке;
- последовательные cache hits и concurrent miss должны иметь одинаковую гарантию изоляции.

Не ограничивайся проверкой `first is not second`: проверь отсутствие общих mutable-вложенных объектов.

## Дефект 2: single-flight начинается слишком поздно

Сейчас каждый вызов сначала самостоятельно выполняет `cache.get()`, а в `_inflight` входит только после получения cache miss.

Возможная гонка:

1. два вызова одновременно начинают `cache.get()` одного ключа;
2. оба cache adapter логически фиксируют отсутствие значения;
3. первый `get()` быстро возвращает `None`;
4. первый вызов рассчитывает карту, записывает её в кэш и удаляет `_inflight`;
5. второй, задержанный `get()`, возвращает ранее зафиксированный `None`;
6. второй вызов не видит `_inflight` и повторно запускает движок.

Требуемое поведение:

- для перекрывающихся вызовов с одинаковым calculation key весь цикл разрешения должен координироваться одной single-flight операцией;
- координация должна учитывать не только `engine.calculate()`, но и cache lookup, чтобы задержанный или устаревший ответ `cache.get()` не запускал второй расчёт;
- N одновременно выполняющихся запросов одного ключа при cache miss должны вызывать `engine.calculate()` не более одного раза;
- разные ключи по-прежнему должны обрабатываться параллельно;
- после завершения или ошибки запись `_inflight` должна корректно удаляться;
- после ошибки следующий самостоятельный вызов должен иметь возможность повторить расчёт;
- отмена одного waiter не должна отменять общий расчёт и ломать результаты остальных;
- ошибки общего расчёта должны корректно передаваться всем ожидающим;
- не добавляй временные задержки или TTL-костыли для удержания завершённой `_inflight` записи.

## Метрики и логирование

Сохрани существующие события и смысл счётчиков `hits`, `misses`, `stale`, `corrupt`, `put_ok`, `put_failed` и `cache_errors_total`, насколько это возможно.

Если перенос cache lookup внутрь single-flight меняет подсчёт конкурентных обращений, выбери и зафиксируй последовательную семантику. Не допускай двойного увеличения счётчиков из-за внутренних повторных проверок кэша.

## Обязательные тесты

Добавь детерминированные async-тесты без ненадёжных `sleep`:

1. Несколько одновременных cache miss одного ключа вызывают движок ровно один раз.
2. Cache lookup входит в single-flight: задержанный или зафиксировавший старый miss запрос не приводит ко второму вызову движка после завершения первого.
3. Все concurrent callers получают равные по содержимому, но разные экземпляры `ChartArtifact`.
4. Изменение `chart` и хотя бы одного вложенного mutable-объекта первого результата не влияет на второй результат.
5. Отмена одного waiter не отменяет leader и других waiter.
6. Ошибка движка передаётся всем waiter, `_inflight` очищается, следующий вызов выполняет новый расчёт.
7. Разные calculation keys не блокируют друг друга.
8. Cache hit также возвращает изолированный от ранее выданных результатов объект.

Используй `asyncio.Event` и управляемые fake cache/engine для воспроизведения порядка событий. Не основывай тесты на реальном времени или случайных задержках.

## Ограничения

- Не исправляй в этой ветке другие замечания ревью.
- Не меняй нормализацию времени и координат в calculation key.
- Не меняй эфемериды, CLI, LLM gateway и logging.
- Сохрани публичную сигнатуру `ChartArtifactResolver.ensure_chart()`.
- Избегай глобальной блокировки: синхронизация должна быть по calculation key.
- Не маскируй ошибки кэша или движка.
- Не создавай коммит без отдельного указания.
