# ADR-0004. `tools[]` и `topics[]` — разные списки

Дата: 2026-08-21. Статус: принято.

## Контекст

Сценарий «транзиты» требует расчёта натала, потому что транзитные аспекты строятся
к точкам натальной карты. Но пользователь спросил только про транзиты — натал здесь
служебная зависимость, а не тема ответа.

При этом сценарий «натал и транзиты» использует ровно тот же набор инструментов,
но обе техники являются темами.

## Решение

В определении сценария два независимых списка:

- `tools[]` — что и в каком порядке считать, включая служебные зависимости,
  с указанием, как результат предыдущего шага попадает в аргументы следующего;
- `topics[]` — что реально идёт в промпт: `{tool, recipe, mode}`.

Примеры:

| Сценарий | tools | topics |
|---|---|---|
| `transit` | natal, transit | transit (full) |
| `natal_and_transit` | natal, transit | natal (compact), transit (compact) |

## Альтернативы

Выводить темы из числа отработавших инструментов. Отвергнуто: даёт неверный ответ
в обоих примерах выше — они неразличимы по составу инструментов.

## Последствия

- Связывание шагов задаётся декларативно в записи сценария, а не общим резолвером
  графа зависимостей: набор техник конечный и известен на этапе написания кода.
- `InterpretationPlan.prompt_recipe: str` заменяется на `topics[]`.
