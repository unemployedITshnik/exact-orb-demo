# ADR-0011. Extractor: rule-based, затем локальная модель; профили в шлюзе

Дата: 2026-08-21. Статус: принято.

## Контекст

Первая версия должна работать без затрат на модель при понимании запроса.
В дальнейшем планируется локальная модель (класса 8B), чтобы не платить за облако.

## Решение

`Intent Extractor` оформляется портом с адаптерами: `RuleBasedExtractor` (v1),
`LocalLLMExtractor`, `RemoteLLMExtractor`; выбор через конфигурацию.

Для rule-based версии переиспользуются `MONTHS_RU` и `INPUT_PATTERN` из `cli.py`.
Темы и фокусы распознаются словарями ключевых слов. Место рождения экстрактор
только помечает кандидатом, подтверждает его геокодер — так экстрактор не обязан
знать список городов.

Экстрактор возвращает уверенность/полноту разбора: при низкой уверенности
оркестратор уходит в уточнение.

Для локальной модели предполагается ограниченное декодирование по схеме
(грамматики GBNF, guided decoding): маленькие модели плохо следуют свободным
инструкциям, но приемлемо заполняют фиксированную схему.

**Шлюзу требуются профили по назначению**: сейчас резолвится одна модель на всё
приложение, из-за чего локальная модель извлечения поехала бы писать разбор
пользователю.

## Альтернативы

Сразу облачная модель для извлечения. Отвергнуто по стоимости.
Форма ввода вместо разбора текста. Отвергнуто: интерфейс — чат (ADR-0012).

## Последствия

- Доля «не разобрал» в v1 выше, поэтому `Clarification` — основной механизм, а не подстраховка.
- Экстрактор не знает каталога сценариев: он про язык, Planner про политику.
- Intent — первый кандидат на вынос в отдельный сервис: у локальной модели свой
  профиль ресурсов.
