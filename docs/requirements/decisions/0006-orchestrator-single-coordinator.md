# ADR-0006. Оркестратор — единственная точка координации, stateless

Дата: 2026-08-21. Статус: принято.

## Контекст

Рассматривался конвейер «канал → контекст → intent → оркестратор». В нём связывание
первых трёх шагов не принадлежит никому явно, и точка входа тихо становится вторым
координатором.

## Решение

Запрос из точки входа попадает сразу в оркестратор; контекст и intent вызываются им
как зависимости. Точка входа остаётся транспортом (аутентификация, лимиты,
сериализация) и не знает о внутреннем устройстве обработки.

Оркестратор stateless: в `self` только зависимости, сконфигурированные на старте.
Состояние живёт во внешних хранилищах, доступных всем репликам.

Оркестратор содержит только последовательность вызовов и ветвлений: не парсит текст,
не знает состава сценариев, не знает устройства промптов.

## Альтернативы

Контекст как обёртка снаружи оркестратора, делающая его чистой функцией
`(контракт, контекст) → (ответ, дельта)`. Отвергнуто: не позволяет сохранить
незакрытое уточнение сразу в момент решения спросить — при сбое на выходе вопрос
уйдёт пользователю, а система о нём не вспомнит.

## Последствия

- Возврат из уточнения («это ответ или новая тема?») решается в одном месте.
- Реплики взаимозаменяемы: второй ход диалога может обработать другой процесс.
- Ожидание чужого I/O должно быть асинхронным, иначе каждое ожидание держит поток.
- Риск god-object; противоядие — отсутствие предметных знаний в оркестраторе.
