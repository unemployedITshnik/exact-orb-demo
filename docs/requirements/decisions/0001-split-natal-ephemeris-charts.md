# ADR-0001. Разделение `natal.py`: примитивы в `ephemeris`, техника в `charts`

Дата: 2026-08-21. Статус: принято, не реализовано.

## Контекст

`engine/ephemeris/natal.py` (33 КБ) держит одновременно два слоя: низкоуровневые
примитивы эфемерид (модели позиций, домов, углов, расчёт тел через `swisseph`,
таблицы управителей, нормализация градусов, юлианские дни) и оркестрацию именно
натальной карты (`calculate_natal`, `NatalChart`, интерцепции, управители домов).

Файл уже негласно работает общим ядром: `charts/transit.py`, `ephemeris/points.py`
и `ephemeris/selena.py` импортируют из него примитивы, включая приватные имена
(`_calculate_houses`, `_normalize_degrees`, `_to_utc` и другие) — то есть через
границу модуля и через границу пакета.

Пакет `engine/charts/` уже существует, и его докстрока прямо заявляет
«chart-level calculations built on deterministic ephemeris data».

## Решение

Разделить файл на два:

- `engine/ephemeris/core` — примитивы, ничего не знающие о натальной карте как о технике;
- `engine/charts/natal.py` — `calculate_natal()`, `NatalChart` и связанные типы.

`points.py`, `selena.py`, `transit.py` импортируют примитивы из `core`.
`transit.py` получает `NatalChart` от соседа по пакету `charts`.

## Альтернативы

Оставить как есть и договориться не расширять. Отвергнуто: соляр, дирекции,
прогрессии и синастрия потребуют тех же примитивов, и каждая новая техника будет
тянуть приватные имена из чужого файла, укрепляя зависимость.

## Последствия

- Затронуто около десяти файлов, правки только в путях импорта, логика не меняется.
- Тесты должны остаться зелёными без изменений по существу.
- `engine/charts` становится местом для всех техник, выводящих позиции из эфемерид.
- Место синастрии остаётся открытым: она сравнивает готовые карты, а не выводит позиции.
