# ADR-0001. Примитивы в `ephemeris`, техники в `charts`; единый `calculate_*` API

Дата: 2026-08-21. Ревизия: 2026-08-25 — контекст приведён к фактическому коду;
добавлены naming convention и правило зависимостей; отменено следствие
«затронуто около десяти файлов». Ревизия: 2026-09-01 — зафиксирована семантика
границ будущего `exact_window`.
Статус: принято. Структурное разделение реализовано, naming convention — нет.

## Контекст

Исходно `engine/ephemeris/natal.py` держал примитивы и натальную технику вместе,
а соседи тянули из него приватные имена через границу пакета. Структурная часть
**выполнена**: `ephemeris/types.py` (модели, таблицы), `ephemeris/calc.py`
(операции), `charts/natal.py` (`calculate_natal`, `NatalChart`),
`charts/transit.py` (`calculate_transits`, `TransitChart`). Приватных имён через
границу пакета не осталось.

Открытым остаётся именование: `get_*` обозначает получение существующего,
chart-level функция выполняет вычисление. В коде `get_*` уже нет, но правило
нигде не записано.

## Решение

**`engine/ephemeris`** — foundation, не знающий ни одной техники. Разделение
`types.py` → `calc.py` однонаправленное и является частью решения; слияние
в один `core.py` отвергнуто.

**`engine/charts`** — модуль на технику: `natal.py`, `transit.py`,
`solar_return.py`, `directions.py`, `progressions.py`. Зависит от `ephemeris`
и от deterministic peers `aspects`, `configurations`, `strength`; техники друг
о друге не знают.

**Naming.** Публичная функция техники — `calculate_<technique>()`, единственное
число. `get_*` за чтением существующего (`cache.get`), `load` / `save`
за состоянием.

**Зависимости между техниками** — типизированным аргументом:

```python
def calculate_transit(
    natal: NatalChart,
    moment: datetime,
    location: TransitLocation | None = None,
    *,
    exact_window: TransitWindow | None = None,
) -> TransitChart
```

Порядок вызовов задаётся сценарием (ADR-0004), `charts` оркестратором
не становится.

**Транзитное окно — параметр, не вторая техника.** Техника производит карту
на момент; окно — параметр поиска точных дат и станций. Поэтому
`calculate_transits` → `calculate_transit`, диапазон переезжает в именованный
`exact_window`.

Переход к `exact_window` обязан сохранить замкнутую семантику `[start, end]`
из Т-ТРН-2 и Т-ТРН-14. Точечное окно одиночного момента при нулевой ширине
должно оставаться представимым: через `start == end`, отдельный вариант или
именованный конструктор — конкретная форма выбирается при миграции. Действующие
явные `TransitDateRange` и tuple по-прежнему требуют `end > start`.

## Альтернативы

Один `core.py` — отвергнуто, текущее разделение строже. Общее ядро в `natal.py` —
отвергнуто исходно. `AstrologyCalculator` со всеми техниками — god-object.
Сохранить `get_*` — смешивает вычисление и чтение.

## Последствия

- Осталась правка имени `calculate_transits` и сигнатуры окна; затрагивает
  `cli.py`, `tools/`, `test_transits.py`.
- Golden tests обязаны дать идентичный результат: математика не меняется.
- `__init__.py` пакетов остаются пустыми, реэкспорт не вводится; фасадом
  является `EngineService` (ADR-0002), а не пакет.
- **Известное нарушение слоя:** `ephemeris/types.py` содержит
  `BodyPosition.chart: Literal["natal"]`, докстрока `points.py` — «for natal
  charts». Примитив не должен называть технику; подлежит правке.
- Место синастрии открыто: она сравнивает готовые карты, а не выводит позиции.
