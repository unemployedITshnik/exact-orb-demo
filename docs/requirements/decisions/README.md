# Записи архитектурных решений (ADR)

Формат: контекст — решение — альтернативы — последствия.

Решение действует, пока не появится запись, явно его отменяющая. Номер
не переиспользуется; отменённая целиком запись помечается «Заменено ADR-NNNN».

Запись может быть ревизована на месте, если решение то же, а меняются его
границы, формулировки или следствия. Ревизия несёт строку
`Ревизия: <дата> — <что изменилось>` и явно называет отменяемые следствия
прошлой редакции. Меняется само решение — выпускается новый номер.

## Ревизии 2026-09-04

Разбор блока сессий
(`component_responsibilities/exact-orb_session_requirements.md`) дал две новые
записи и четыре ревизии на месте:

* **0023** заменяет **0010**: запрет на любое долговременное хранение,
  связанное с содержанием ответа, лишал сервис обратной связи о качестве
  интерпретаций. Введены два раздельных корпуса с разными правилами жизни.
* **0024** — реализация хранилищ: три ступени `InMemory` / `Sqlite` /
  `Postgres` за одними и теми же портами, условие перехода, отказ от Redis.
* **0009** — `SessionProfile` → `SessionState`, диалог вынесен в отдельную
  запись, введён абсолютный потолок TTL, `DeleteMyDataCommand` гасит cookie;
  **отменена** безусловность следствия «TTL продлевается любой операцией»;
  `ProfileService` как отдельный компонент не вводится.
* **0013** — IP-лимит привязан к классу операций: класс `calculation`
  бюджет не расходует, но занимает единственный слот сериализованного
  движка. Добавлены сессионные лимиты построения и ключ кэша интерпретаций.
* **0014** — `profile_version` → `state_version`, `ContextDelta` →
  `StateDelta`; зафиксирован контракт `compare_and_set` и третий исход
  `AlreadyApplied`; **отменено** следствие про сброс производного вида
  в MVP.
* **0016** — в MVP сессия хранит одну карту: `derived_chart`, `active_view`
  и `SetActiveView` отсутствуют вместе с транзитами. Условие снятия названо.

Слаг `0010-journal-split.md` остаётся при заменённой записи: номер
не переиспользуется, файл сохранён как история решения.

## Ревизии 2026-09-05

Реализация процессного session persistence уточнила границы уже принятых
lifecycle-решений:

* **0009** — `touch` остаётся единственным read-and-renew; фасетные
  `get`/`read` read-only, а успешные CAS/append/clear являются
  write-and-renew. Append продлевает state и dialog одним deadline, clear
  продлевает state без изменения content/version и удаляет dialog. Неуспех
  любой части обязательного touch даёт единый fail-closed `StateReadFailed`,
  который сам по себе не доказывает утрату persisted-сессии.
* **0014** — `Superseded` означает mismatch actual и intent, а не доказанную
  победу конкурентного запроса; `AlreadyApplied(0)` допустим для уже пустой
  fresh-сессии. Save с `RESET_DELTA` и reset-all классифицируются одинаково.
* **0024** — SQLite append/clear обязаны выполнять то же изменение одной
  `BEGIN IMMEDIATE … COMMIT`; parent state является единственным источником
  liveness, а persisted dialog deadline является lifecycle-зеркалом и не
  является независимым liveness-предикатом.

## Ревизии 2026-09-06

* **0006, 0011, 0017, 0019, 0020** — ссылки на session-модель приведены к
  уже принятым именам `SessionState`, `StateDelta`, `state_version` и к
  сужению MVP до одной базовой карты. Архитектурный смысл этих решений не
  менялся.
* **0023** — полный категориальный вектор больше не объявляется unlinkable:
  схема гарантирует отсутствие прямых и восстановимых ID, а остаточная
  корреляция и бессрочный retention приняты отдельно. `response_text`
  исключён из always-on корпуса, quality вынесено в append-only events,
  Research v1 ограничен natal/cosmogram, а digest format v1 зафиксирован.
  P5a реализует contracts, whitelist-проекцию и InMemory adapter; SQLite P5b
  и application wiring остаются отдельными незавершёнными этапами.
* **0024** — P4 реализует session SQLite adapters: per-operation connections,
  внешний executor, component-scoped migrations, one-shot parent-only reaper
  с `ON DELETE CASCADE` и full-adapter benchmark с отдельным датированным
  отчётом. P4.1 отделяет подтверждённый transaction outcome от cleanup,
  расширяет однократный WAL recovery на non-`wal` read-back и закрепляет
  совместимость payload v1 frozen fixture.

## Ревизии 2026-09-07

* **0017** — закрыт вопрос полноты спецификации (Т-ГРН-7). Параметры,
  влияющие на числа, но не выбираемые пользователем, покрываются
  `CalculationVersion`, а не полями `ChartSpec`: отпечаток расширен до девяти
  компонент, из них три новые — методика Селены, набор тел по умолчанию и
  эффективные флаги эфемерид. `ephemeris_path` намеренно исключён из отпечатка,
  чтобы один и тот же набор файлов по разным путям давал один ключ.
  **Отменено** следствие прошлой редакции, оставлявшее полноту ключа открытым
  вопросом. Форма `ChartSpec` не меняется, поэтому ветка A1b
  `refactor/chart-spec-completeness` снята из roadmap, а `BuildNatalHandler`
  перестал зависеть от блока A по контракту. Условие возврата к полному
  `ChartSpec` — появление пользовательского выбора любого из замороженных
  параметров.

## Решения 2026-09-09

* **0025** — на реализованном пути Build Natal введены парные DEBUG-события

## Решения 2026-09-11

* **0027** — удалены независимые дубликаты `chart_kind` и `warnings` из
  расчётных envelope; каноническими остаются `ChartSpec` для намерения и
  `NatalChart` для результата. Локальные и сквозные validators связывают
  resolved birth data, спецификацию, карту, `calculation_key`, артефакт и
  `StateDelta`. Отдельная `artifact_schema_version` не вводится.
* **0028** заменяет **0026**: summary внутренних границ не позволял найти
  место рассинхронизации данных. Все пять границ снова пишут полные входы и
  выходы только в DEBUG, сохраняя единый envelope и явный блокер публичного
  развёртывания из-за персональных данных в локальном журнале.
* **0029** заменяет только часть **0023** о преобразовании псевдонимов точек в
  Research projection. `bodies`, аспекты, конфигурации, натальные цели
  транзитов и Research v1 используют единые `true_node`, `south_node`,
  `mean_apog`, `pars_fortune`; aliases остаются presentation-терминами.
  Состав Research v1, privacy, retention и consent из ADR-0023 не меняются.

## Решения 2026-09-12

* **0030** заменяет оставленное **0029** решение считать `true_node` и
  `south_node` независимыми участниками отношений. `true_node` представляет
  ось в аспектах, конфигурациях, транзитах и station-aspects; `south_node`
  остаётся производной позицией в `bodies`. Исключение выполняется до поиска
  аспектов, без эвристической дедупликации. Меняется `CalculationVersion`, но
  отдельные artifact и Research schema versions не вводятся.
* **0031** закрывает оставленные **0029** и **0030** вопросы целостности
  materialized-конфигураций. `NatalChart.aspects` является каноническим
  списком, полные вложенные `Aspect` обязаны точно ему соответствовать, а роли,
  топология, `max_orb`, `chart` и `contains` проверяются агрегатом.
  `configurations` теперь требует `aspects`; corrupt payload пересчитывается.
  Методика и валидный результат не меняются, поэтому версии не увеличиваются.
* **0032** частично заменяет **0008** в части аспектов космограммы. При
  отсутствующем времени возможны все валидные минуты локальной даты;
  публикуются только аспекты с неизменными типом и категорией, а их `orb`
  является консервативным максимумом. Исключённые пары описывает отдельный
  типизированный `time_uncertainty`; конфигурации строятся только из
  устойчивых рёбер. Реализованы key v2, `ENGINE_VERSION="4"`, state payload
  v2 и чтение frozen state payload v1.
