# ADR-0009. Контекст диалога есть, профили субъектов отложены

Дата: 2026-08-21. Статус: принято, первый этап.

## Контекст

Под словом «контекст» скрываются разные по времени жизни вещи: незавершённый запрос,
данные субъектов, кэш расчётов, история диалога. Складывать их в один компонент —
та же ошибка смешения ответственностей, что и в `natal.py`.

## Решение

`Context Manager` — фасад, за которым разные хранилища, а не один мешок.
На первом этапе:

- **есть** `Session Store` с TTL: частично заполненный контракт,
  `pending_clarification`, последние ходы диалога;
- **нет** долговременных профилей субъектов: данные рождения живут в сессии.

Контекст вызывается оркестратором (`load` / `save`), а не оборачивает его.
Хранилище внешнее по отношению к процессу.

## Альтернативы

Завести профили сразу. Отложено: тянет за собой согласие на обработку персональных
данных и удаление по запросу.

## Последствия

- Каждый новый диалог начинается с запроса данных рождения — принятый UX-долг.
- В пределах одного разговора повторять данные не нужно.
- Решение пересматривается при появлении аккаунтов: с личным кабинетом хранение
  данных рождения становится ожидаемым.
- Кэш расчётов инвалидации не требует: правка данных даёт другой ключ.
