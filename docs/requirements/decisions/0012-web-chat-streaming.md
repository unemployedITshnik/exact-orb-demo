# ADR-0012. Веб-чат со стримингом; оркестратор — источник событий

Дата: 2026-08-21. Статус: принято.

## Контекст

Интерфейс первой версии — веб-чат со свободным вводом (не форма), анонимная сессия
в куке. Интерпретация занимает секунды, и ожидание без обратной связи ощущается плохо.

Шлюз сейчас явно запрещает `stream=True` в `_reject_ambiguous_kwargs`.

## Решение

Ответ отдаётся потоком (SSE). Оркестратор перестаёт быть функцией, возвращающей
готовый объект, и становится источником типизированных событий:

- `status` — стадии детерминированной середины;
- `clarification` — уточняющий вопрос вместо интерпретации, поток закрывается;
- `token` — куски текста модели;
- `done` — финал с метаданными и предупреждениями;
- `error` — только событием внутри потока: после отдачи 200 HTTP-код уже не изменить.

В шлюз добавляется `complete_stream()` рядом с `complete()`; последний остаётся
для профиля извлечения. Два метода, а не флаг.

Финализация (запись в историю и контекст) выполняется после конца потока,
с накоплением текста по мере отдачи.

## Альтернативы

Обычный запрос-ответ со спиннером — проще, но хуже ощущается на многосекундном тексте.
Фоновая задача с опросом — устойчивее, но требует очереди и воркеров; отложено.
Форма ввода вместо чата — отвергнуто, выбран чат.

## Последствия

- Форма основного метода оркестратора определена до написания кода вокруг него.
- В чате многоходовость — норма, поэтому контекст переезжает в ранний этап работ.
- Требуется обработка обрыва соединения: токены оплачены, полученное разумно сохранить.
- Публичный анонимный чат требует защиты от расхода токенов (ADR-0013).
