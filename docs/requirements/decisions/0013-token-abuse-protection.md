# ADR-0013. Защита бюджета по классам операций; `AdmissionControl`

Дата: 2026-08-21. Ревизия: 2026-08-25 — admission выделен в компонент; введена
атомарная резервация бюджета с lease; учёт переведён на стоимость.
Статус: принято.

## Контекст

Исходный ADR рассматривал публичный чат как один тип нагрузки. После разделения
операций стоимость различается принципиально, а защита была описана как набор
мер без владельца.

## Решение

Квоты считаются по дорогостоящим interpretation operations, не по HTTP-запросам.

| Класс | LLM | Доступен | Расходует бюджет |
|---|---|---|---|
| `calculation` | нет | всем | нет |
| `preset_interpretation` | да | всем | да |
| `freeform_interpretation` | да | по подписке | да |

**Ограничения ставятся с обеих сторон.** Длина вопроса ограничивается
`InputGuard` на входе, объём ответа — `max_tokens` на выходе. Учёт ведётся
в стоимости, а не в токенах: вход и выход тарифицируются по-разному.

**`AdmissionControl`** — владелец допуска и стоимости, с тремя точками вызова:

```
на транспорте    access check, IP rate limit
перед intent     abuse signals + GuardVerdict
перед LLM        atomic reserve → commit | cancel
```

Резервация атомарна и выполняется **только при промахе interpretation cache**.
Запись резервации обязана иметь lease с TTL и reaper: падение процесса между
`reserve` и `commit` иначе протекает бюджетом (ADR-0006).

**Иерархия защиты, от мягкой к жёсткой:**

1. лимит длины входа и `max_tokens` на ответ — на каждый вызов;
2. кэш интерпретаций — повтор не оплачивается дважды;
3. лимит стоимости на сессию — защищает от честного перерасхода, но **не
   является защитой от злоупотребления**: сессия анонимна и сбрасывается вместе
   с cookie;
4. лимит по IP и CAPTCHA при необходимости;
5. **глобальный дневной потолок** — единственная мера, которую нельзя обойти,
   с деградацией сервиса при достижении.

**Значения лимитов.** Предварительные задаются с первого дня: публичное demo
без них выкатывать нельзя. Потолок считается из юнит-экономики — стоимость одной
интерпретации умножить на приемлемый дневной расход. Фокус-группа на MVP уточняет
другое: хватает ли пользователю сессионного лимита для осмысленной работы. Эти
два числа приходят из разных источников и совпадать не обязаны.

Пользовательский текст никогда не используется как инструкция для Engine
или Tool Runtime (ADR-0018).

## Альтернативы

Одна квота на все запросы — отвергнуто. Ограничивать только исходящие токены —
отвергнуто: вход это то, чем управляет пользователь. Запретить raw text на пути
к LLM — отвергнуто для полноценного диалога. Передавать raw prompt без
preprocessing — отвергнуто.

## Последствия

- Перестроение карты и `InputRequired` не сжигают interpretation quota.
- Аналитика различает три класса операций (ADR-0010).
- Разделение `AdmissionControl` на `RateLimiter` и `BudgetReservation` остаётся
  открытым вопросом связности.
