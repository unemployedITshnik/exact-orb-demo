# Sequence diagrams — блок АРТЕФАКТЫ

Увеличение блока `ChartArtifactResolver → calculation_key → CalculationCache
→ EngineService` из диаграмм `../build_natal/`. Контракты, требования
и полный разбор сценариев —
`docs/requirements/component_responsibilities/exact-orb_chart_artifacts.md`.

Диаграммы изолированы относительно модуля: вызывающий показан одним
участником, сессия, транспорт и Agent Runtime не участвуют.

| Файл | Сценарий | Исход |
|---|---|---|
| `001-ensure_chart_miss.puml` | A-1 (§5.2): промах, расчёт, запись | `ChartArtifact` |
| `002-ensure_chart_hit.puml` | A-2 (§5.1): попадание; ветки `cache_stale` и `cache_corrupt` | `ChartArtifact` без вызова движка |
| `003-ensure_chart_calculation_failed.puml` | A-3 (§5.3): три причины отказа, два класса | `ChartCalculationError` / `CalculationUnavailableError` |
| `004-single_flight_concurrent_miss.puml` | A-4 (§5.6): параллельный промах по одному ключу | один расчёт на всех ожидающих |
| `005-cache_degraded_fail_open.puml` | A-5 (§5.5, §5.7): отказы `get` и `put`, дросселирование | операция успешна, кэш деградирован |
| `006-ensure_derived_composition.puml` | A-6 (§4): композит из базовых артефактов | `ChartArtifact` производной карты |

Сценарий §5.4 (успешная запись) отдельной диаграммы не требует: он совпадает
с A-1, а его содержательное требование сформулировано от противного —
успешная запись не является условием возврата результата.

## Что диаграммы фиксируют помимо порядка вызовов

- **001** — где строится ключ и почему из проекции; где выбирается техника;
  кто собирает `ChartArtifact`; почему предпроверка спеки стоит до захвата
  `ephemeris_session()`.
- **002** — две аварийные ветки, обе с алертом: `cache_stale` (payload
  валиден, но не тот — дефект ключа) и `cache_corrupt` (payload не читается).
  В исправной системе ни одна сработать не может.
- **003** — разделение отказов по признаку «кто это чинит» и отображение
  класса исключения в класс исхода.
- **004** — `asyncio.Task` + `shield` вместо ручного `Future`: отмена любого
  ожидающего, включая лидера, не отменяет расчёт. Плюс `singleflight_join`
  с двумя идентификаторами: собственным и лидера.
- **005** — fail-open на обеих операциях кэша, отдельный `cache_timeout_ms`
  внутри адаптера и правило «дросселируется журнал, но не метрика».
- **006** — ключ композита из ключей частей; отсутствие рекурсии внутри
  `ensure_*`.
